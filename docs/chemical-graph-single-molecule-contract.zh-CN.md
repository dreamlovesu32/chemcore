# ChemicalGraph 单分子语义契约

## 边界

ChemicalGraph 是 ChemSema 面向系统命名和核磁预测的严格语义中间表示，只表示一个确定的分子实体，或一个具有整数计量比的离散分子组合。CCJS 仍然是可编辑文档格式。

ChemicalGraph 不表示坐标、字体、颜色、标题、反应、查询结构、Markush、聚合物、非整数混合物和页面布局。这些内容属于 CCJS，或属于未来使用新 schema 标识的其他 profile。

## 字段分层

| 类型 | ChemicalGraph 字段 | 规则 |
| --- | --- | --- |
| 权威分子事实 | 原子序数、同位素、形式电荷、自由基、已解析隐式氢、键类型及配位方向、立体元素、组分计数、多中心相互作用 | 必须序列化、校验，并参与身份判断 |
| 规范化派生事实 | 芳香表示、价态及隐式氢解释、组分连通性 | V2 固定其解释；生产者必须在导出前解析完成 |
| 来源说明与明确边界 | `assumptions` | 必须校验；不得用它代替缺失的分子事实 |
| 绘图表现 | 坐标、包围盒、标签、字体、颜色、键图元 | ChemicalGraph 禁止携带，保留在 CCJS |

## V2 兼容决策

既有 `chemsema-nomenclature/chemical-graph/2` 已经定义为 V1 字段加 `interactions`，因此继续保持这个线格式：

- 旧文件没有 `semantics` 时，按固定的 V2 语义读取；
- 导出 `semantics` 时，它只能等于 V2 固定 profile，不能选择另一套身份规则；
- 不把相互作用电子数添加到 V2，因为它是可变分子事实，旧 V2 读取器会静默忽略；
- 只有“旧读取器忽略后不会改变分子身份或解释”的字段，才允许在 V2 内增补；
- 未来任何新的可变身份字段都必须使用新 schema，并提供显式适配器。

## 规范化规则

每个生产者必须：

1. 拒绝查询、伪原子、外部连接点、反应和聚合物语义；
2. 将每个原子解析为确定的元素、同位素、电荷、自由基和隐式氢数；
3. 明确表示芳香键，不从绘图形状猜测身份；
4. 将来源格式的多中心约定转换成原生 `interactions`；
5. 将支持的来源立体信息转换成原生立体元素；
6. 对畸形或尚不支持的身份信息明确报错，不得丢弃或 fallback；
7. 使用普通键和多中心相互作用共同计算组分。

## 适配验收矩阵

| 来源或目标 | 接受 | 明确拒绝 |
| --- | --- | --- |
| CCJS 分子片段 | 完整选中的单个确定分子；支持的键、立体和原生相互作用 | 局部选择、查询、外部连接点、聚合物、错误语义引用 |
| CDXML/CDX | 确定分子、增强立体、配位键、校验通过的 `MultiAttachment` 配位模式 | 歧义或畸形多连接拓扑，以及尚不支持的身份对象 |
| SMILES | 化学解析器支持的确定连接分子 | SMARTS 查询、文档语义、解析图无法表达的来源含义 |
| 命名/NMR 请求 | 校验通过的 V2 | 错误 schema、未解析语义、静默降级 |

## 身份与相等

ChemicalGraph 身份忽略局部 ID、数组顺序、组分顺序和绘图几何；包含全部权威分子事实。同一个规范化分子的不同画法必须相等。改变同位素、电荷、自由基、氢数、立体描述、组分计数、配位方向或多中心相互作用，必须改变身份。
